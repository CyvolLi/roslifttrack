# Lifttrack 机械设计项目仓库

本项目面向小组开发成员，统一存放机械设计相关文档与资料。

## 目录结构

| 目录 | 存放内容 | 说明 |
|------|---------|------|
| `designbook/` | 设计方案、设计结构、设计标准 | 设计思路、结构说明、团队设计规范 |
| `designsource/` | 自研机械结构源文件 | 自己设计的 3D 模型、2D 图纸源文件 |
| `productsource/` | 成品产品标准书 | 外购成品的规格书、选型手册、标准书 |

## 基础开发规范（必读）

### 1. 文件命名

统一使用以下格式，禁止出现中文空格、特殊字符（`# % & *` 等）：

```
[类别]_[项目/部件名]_[版本].后缀
```

示例：`LIFT-01_导轨装配_V1.2.sldasm`、`designbook_升降方案_V0.1.docx`

- 版本号：`V1.0` / `V1.1` / `V2.0`，修订小改升小版本，结构大改升大版本
- 日期不写入文件名，以 Git 提交记录为准

### 2. Git 使用

- **只提交必要文件**：源文件（SolidWorks：.sldprt/.sldasm）+ 最终 PDF，不提交临时文件、缓存、中间过程文件
- **提交信息格式**：

```
[类型] 内容描述

类型：新增 / 修改 / 修复 / 删除
```

示例：`[新增] 导轨总装 SolidWorks 模型 V1.0`

- 多人协作时，谁改谁提交，并在提交信息里写清楚改了什么
- 不要直接覆盖别人的文件，有冲突先沟通再合并

### 3. 版本管理

- 重要节点（评审通过、发版）请提交并标注版本号
- 每个目录内的版本规则详见该目录 README

### 4. 提交前检查清单

- [ ] 文件命名符合规范
- [ ] 没有临时/中间文件混入
- [ ] 提交信息写清楚改动内容
- [ ] 文件能正常打开（模型、图纸无缺失）

## 常用 Git 命令速查

```bash
git status              # 查看改动
git add 文件名           # 添加文件
git commit -m "[新增] 描述"   # 提交
git pull                # 拉取最新
git push                # 推送
```

> 新成员第一次使用仓库，先读完三个子目录的 README 再开始干活。
