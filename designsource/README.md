# Designsource — 自研机械结构源文件

存放**自己设计的机械结构**：3D 模型、2D 工程图、装配体等源文件。

## 存放内容

| 类型 | 格式 | 说明 |
|------|------|------|
| 3D 零件/装配体 | SolidWorks 源文件（`.sldprt`/`.sldasm`） | 团队统一使用 SolidWorks，外发时另存 STEP |
| 2D 工程图 | 源文件 + `.pdf` | PDF 用于评审、存档 |
| 计算/分析文件 | `.xlsx` / `.docx` | 强度、干涉等分析记录 |

> 建议：源文件 + 交换格式**成对提交**，方便没有对应 CAD 软件的成员查看。

## 目录组织

按总装 → 部件 → 零件 的层级组织：

```
designsource/
├── LIFT-00_总装/
│   ├── 总装_V1.0.sldasm
│   └── 总装_V1.0.pdf
├── LIFT-01_导轨部件/
│   ├── 导轨零件_V1.0.sldprt
│   └── 滑块零件_V1.0.sldprt
└── LIFT-02_驱动部件/
```

## 命名规范

```
[总成编号]-[部件名]_[零件名]_[版本].后缀
```

示例：`LIFT-01_导轨部件_上导轨_V1.0.sldprt`

## 版本与协作规则

1. **每个成员只修改自己负责的部件**，改动前先 `git pull` 拉取最新
2. 版本号变更规则：
   - 结构未变、只做修正 → 不升版本，直接覆盖并提交
   - 结构有改动 → 升小版本（`V1.0` → `V1.1`）
   - 装配关系/接口变化 → 升大版本（`V1.x` → `V2.0`），并同步更新 `designbook` 中的结构说明
3. 发布前必须检查：零件无缺失、装配无报错、图纸与模型一致

## 提交检查清单

- [ ] 源文件（.sldprt/.sldasm）与 PDF 成对提交
- [ ] 装配体中引用的零件都已包含
- [ ] 提交信息写明改了哪个部件、为什么改
